# 第五步：旧备份迁移到账户

此功能把浏览器原型导出的完整 JSON 备份迁移到本机 PostgreSQL 账户。训练计划仍为规则模板或用户确认的草稿；不产生真实 AI 分析，也不迁移身体照片。

## 页面操作

1. 在原浏览器版（例如 3002）进入“训练记录”，导出完整 JSON 备份，并保留原文件。
2. 打开 http://127.0.0.1:3100/，登录目标账户，进入“训练记录 → 迁移旧备份到账户”。
3. 选择文件。此时只在页面内存读取，尚未发送到后端；可下载一份原始文件副本。
4. 点击“后端预览”，核对来源、新增、跳过条数以及版本映射和提醒。
5. 勾选已保留备份并核对，点击确认。确认完成后账户页面重新加载，训练和回顾页面可查看结果。

仅支持练序 v2 完整备份，UTF-8 最大 5 MB。不同端口的浏览器记录不直接跨页读取，不扫描 localStorage。账户迁移采用追加方式，原始文件及原浏览器记录仍保留；浏览器模式的“完整恢复”仍是另一种操作。

## 如何处理已有记录

- 空账户：采用备份当前资料和计划，写入历史计划、训练及体重。
- 已有账户：保留当前资料，将备份历史计划分配到账户新版本，追加训练/体重，最后建立当前计划副本继续使用。
- 训练、动作和组的稳定编号、记录单位、负重和主观反馈保留；来源计划版本映射到新编号，保存来源版本与任务编号。
- 同编号同内容训练跳过。同编号不同内容、同日不同体重、两份进行中训练等冲突拒绝整批导入，不覆盖原记录。
- 旧体重没有编号时，按日期和数值生成确定编号；同日只有一条且数值相同则跳过。多次测量有歧义时拒绝。
- 千克数值最多三位小数，超精度拒绝，不静默舍入。未知的旧训练动作仍保留其名称与次数/秒数，不用目录近似匹配改写。
- 旧归档缺失的起止时间继续为空。缺少对应计划历史、当前计划与最后历史不符、已有排课快照与解析不一致时拒绝，不伪造历史。

老备份没有排课 days 时，只能按已有规则解析历史计划，预览会提示这一兼容行为；已经记录的动作、目标快照及实际成绩不改写。照片、密钥和未支持的私有扩展字段拒绝，包括嵌套计划扩展。

## 事务、去重与保留期

预览只创建 ImportJob，不修改账户资料、计划、训练或体重。任务有效期为 30 分钟；取消删除待确认任务，过期后无法确认。服务启动和每分钟清理过期任务的 payload。服务停止时不能清理，重新启动时执行清理。

确认锁定账户并比较预览时的业务指纹。其他页面已修改资料或记录时返回 409，必须重新预览。计划、资料、训练、组、体重及回执在同一个数据库事务内写入；后半段失败整批回滚。写入完成后核对新增训练事实及体重值，原文件不变。

规范化备份内容后计算摘要：忽略导出时刻、训练 revision 与对象键顺序。每账户同摘要唯一；重复确认或确认响应丢失后重试返回同一回执，不再添加记录。确认后清空 payload，只保留摘要和汇总回执。重新编辑备份是不同内容，仍需预览并检查冲突。这不是一般写入的离线队列，后者属于第六步。

## 接口

全部接口位于 /api/v1，要求账户会话、精确 Origin、CSRF 和 X-Account-Id；账户归属从会话读取。

| 请求                         | 输入                  | 结果                                                                      |
| ---------------------------- | --------------------- | ------------------------------------------------------------------------- |
| POST /me/imports/preview     | `{text: "备份原文"}`  | id、pending、expiresAt、summary；已确认相同备份返回 confirmed 和原 result |
| POST /me/imports/:id/confirm | `{acknowledge: true}` | confirmed、result、repeated；检查归属、到期和指纹                         |
| DELETE /me/imports/:id       | 无请求体              | 取消待确认任务；不删除已确认回执或业务记录                                |

summary 包含 source/added/skipped 条数、versions 来源与目标对应、keepCurrent、currentVersion 和 warnings。格式问题 400，账户任务不存在 404，冲突 409，到期 410；数据库不可用或事务失败 503，不向页面泄露 SQL 或连接信息。

## 代码学习顺序

1. `public/account-import-view.js`：文件在内存、预览、显式确认、忙碌状态与响应丢失提示。
2. `server/imports.ts`：数据白名单、规范化摘要、版本映射、冲突判断、账户锁和单一事务。
3. `prisma/schema.prisma` 的 ImportJob 与第六份迁移：预览状态及中文表/列说明；完整字典见 BACKEND-FIELDS.md。
4. `server/test/imports.test.ts`：虚构备份展示重复确认、账户隔离、并发改变、过期清理、自定义计划、旧秒数单位、冲突和整批回滚。

验证使用独立测试数据库及虚构记录，不自动导入真实用户资料。一般写入幂等、离线同步、真实 AI 和照片上传仍未实现。

第五步验证：67 项前端/客户端测试与 34 项后端真实数据库测试（共 101 项）通过；check、构建、类型、Prisma、format:check 通过。独立虚构浏览器账户验证文件读取、预览、确认、刷新后旧秒数记录、重复导入不新增、取消预览不写业务表；390 像素迁移弹层无横向溢出，关闭入口位于右上角。验收浏览器及独立数据库服务已关闭，用户原页面和账户不改动。开发数据库第六份迁移已应用，11 张表和 82 个字段均有中文注释；3100 开发服务继续运行。
