# v0.2 训练记录：数据设计与审核

当前分支：`feat/workout-log`。v0.2已完成训练流程、历史、上次成绩与备份界面。初次打开页面时校验并迁移有效旧记录，采用独立v0.2存储键，不删除原始v0.1记录。

## 一次训练如何组织

```text
训练 workout（唯一ID）
├─ 日期、计划名称与版本
├─ 状态 active / completed
├─ 开始时间、结束时间、备注、来源
└─ 动作 exercises[]（每次训练中的独立ID）
   ├─ exerciseId：跨训练比较用的动作标识
   ├─ name：当时的动作名称快照
   ├─ unit：reps 次数 / seconds 秒数
   └─ 训练组 sets[]（唯一ID）
      └─ load 负重、value 次数或秒数、rir、pain
```

训练中的动作ID用于定位编辑，动作库ID用于寻找上次成绩，两者不能混为一谈。计划版本和动作名称保留快照，避免新计划改变旧记录的含义。

开始时间由调用方传入ISO UTC时间，日期由界面按用户时区生成，二者分开保存。完成时间不能早于开始时间；同时只能有一项进行中的训练。组数由sets数量计算，不重复保存可失步的计数。

## 旧记录迁移规则

原有logs没有训练ID和起止时间。按“日期＋计划版本”建立旧版归档，同一归档内按动作名称聚合，组顺序不变。即使两组数值相同也全部保留，不把重复数值认定为重复记录。起止时间为null，不推测实际时长。同日同版本的多次训练无法还原，界面需要明确显示这一局限。

迁移ID根据原始日期、版本和记录位置生成。相同输入结果相同，再处理schemaVersion=2数据只校验并复制，避免重复迁移。旧记录的动作标识暂用名称；接入动作库时增加明确映射，未知动作不能自动合并。

遇到无效日期、未知版本、重复ID或损坏记录时抛出错误，不返回空列表伪装成功。迁移函数不访问localStorage，不修改传入对象，不删除原始数据。

## 已接入的保存与恢复约定

1. 保留旧存储键，建立新的v0.2存储键。
2. 迁移后校验、写入、读回校验成功，才使用新数据。失败提示用户，并保留旧记录与下载备份入口。
3. 完成每组新增/编辑/删除、训练完成及刷新恢复。
4. 使用动作库ID寻找最近一次已完成训练，同名不同单位不直接比较。
5. 备份携带数据版本；导入先预览，以ID检查重复和冲突，确认后再写入。

## 学习与审核入口

先读public/workouts.js的createWorkout，了解一个对象如何表达业务；再读validateWorkoutData，理解为什么不仅检查类型，还检查时间顺序、唯一ID和状态约束；最后读migrateLegacyLogs及对应测试。

输入→校验→返回结果是这个模块的职责。UI负责显示和事件，存储层负责读写和失败恢复。函数不自己读取时间或生成随机ID，测试因此可以重现相同结果。注释解释数据缺失和设计取舍，不重复描述每行语法。

## 本轮验收

- 旧版组数、重量、次数、RIR、疼痛反馈全部保留。
- 同日不同版本分开，同动作各组保持原始顺序。
- 重复执行迁移不会产生新ID或重复组。
- 坏数据明确失败，原始输入不被修改。
- 时间动作和次数动作使用明确单位。
- 页面已采用新版流程，保存失败明确提示；坏数据可下载原始文件，再用有效完整备份恢复。
