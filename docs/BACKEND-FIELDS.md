# 数据库中文字段字典与 Navicat 查看

中文说明已通过第 4 个迁移写入 PostgreSQL 表/列注释，第 5 个迁移更新已实现的训练版本与计划快照说明，并同步到 Prisma 字段说明。注释不改变表名、字段名、数据类型或业务数据。

在 Navicat 刷新连接或关闭后重新打开表，在“设计表”的字段备注/注释区域查看；具体入口名称随版本可能不同。JSON 内部键不是独立数据库列，说明集中在 data、snapshot、prescription 的列注释及相关文档中。

后续新增字段同时维护 schema.prisma 的中文说明和新迁移中的 COMMENT ON COLUMN；已应用的迁移不回头修改。表名和字段名沿用英文稳定标识，中文只作为说明。

## User

用户账户：保存登录邮箱、加盐密码哈希与创建时间；不保存明文密码。

| 字段           | 中文说明                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------ |
| `id`           | 用户唯一编号（UUID，主键）；个人数据通过此编号确定归属。                                   |
| `email`        | 登录邮箱，注册时去除首尾空格并转小写，大小写不敏感唯一；旧虚构账户允许为空，邮箱尚未验证。 |
| `passwordHash` | 加盐 scrypt 密码哈希，含算法版本、随机盐和结果；不是明文密码。为空的旧账户不能登录。       |
| `createdAt`    | 账户创建时刻，带时区时间戳；默认数据库当前时间。                                           |

## Session

登录会话：原始令牌仅在 HttpOnly Cookie 中，数据库只存哈希；退出删除当前会话。

| 字段        | 中文说明                                                                           |
| ----------- | ---------------------------------------------------------------------------------- |
| `tokenHash` | 会话令牌的 SHA-256 哈希，64 位十六进制文本（主键）；不是可直接用于登录的原始令牌。 |
| `sequence`  | 自动递增且唯一的会话创建序号；同一毫秒创建的会话也能确定先后，用于撤销最早的会话。 |
| `userId`    | 所属用户编号，关联 User.id；删除用户时级联删除其会话。                             |
| `createdAt` | 会话创建时刻，带时区时间戳。                                                       |
| `expiresAt` | 会话绝对过期时刻，必须晚于创建时刻；当前有效期七天，不随访问延期。                 |

## Profile

用户当前资料：每个账户一份；JSON 保存原型字段，revision 用于检查并发修改。

| 字段        | 中文说明                                                                                                                                                                                                                                                                                                                      |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `userId`    | 所属用户编号，关联 User.id，同时为主键；每个用户最多一份当前资料。                                                                                                                                                                                                                                                            |
| `data`      | 个人资料 JSON：age 年龄（岁）、height 身高（厘米）、weight 体重（千克）、days 每周训练次数、experience 经验、equipment 环境、goal 目标；可选 availableEquipment 设备、sessionMinutes 分钟、movementPreference 偏好、excludedPatterns 排除类型、restrictionNotes 备注。详细枚举见 docs/PROFILE-DATA.md；备注不作自动医疗判断。 |
| `revision`  | 资料修改版本，初始为 1；保存时提交 expectedRevision，版本不一致返回冲突，不应手工覆盖版本。                                                                                                                                                                                                                                   |
| `updatedAt` | 资料最后更新时间，带时区时间戳；由 Prisma 写入时维护，直接 SQL 更新不会自动刷新此字段。                                                                                                                                                                                                                                       |

## Exercise

公开动作文字资料库：18 条内置与 1324 条社区资料；不含第三方图片、GIF 或视频。

| 字段               | 中文说明                                                                                   |
| ------------------ | ------------------------------------------------------------------------------------------ |
| `id`               | 动作稳定编号（主键），例如 lianxu:plank 或 hasaneyldrm:2137；译名改变不改变动作身份。      |
| `nameZh`           | 中文动作显示名；社区译名尚未经过专业教练逐项审校。                                         |
| `nameEn`           | 来源中的英文原名；内置动作没有英文名时为空字符串。                                         |
| `bodyPart`         | 训练部位的原始标签，例如 shoulders 肩部、waist 腰腹；API 按原始标签筛选，前端显示中文。    |
| `equipment`        | 所需设备的目录标签；社区资料使用原始标签，内置资料使用练序设备编号，不应直接视为统一枚举。 |
| `target`           | 主要目标肌群的目录标签，例如 quads 股四头肌、abs 腹肌。                                    |
| `secondaryMuscles` | 辅助肌群标签数组；空数组表示没有提供辅助肌群资料。                                         |
| `stepsZh`          | 中文动作教学步骤数组，按数组顺序展示。                                                     |
| `stepsEn`          | 英文来源教学步骤数组；没有提供时为空数组。                                                 |
| `unit`             | 记录单位：reps 次数、seconds 秒、unspecified 未指定；社区动作进入训练前必须确认明确单位。  |
| `origin`           | 动作来源：builtin 练序内置文字、community 社区文字资料。                                   |
| `sourceId`         | 来源中的原始动作编号；与练序统一稳定编号 id 区分。                                         |
| `sourceCommit`     | 社区来源 Git 提交号，用于追溯固定数据版本；内置动作可为空。                                |
| `mistake`          | 常见错误或动作注意事项，可为空；不代表个体医疗诊断。                                       |
| `updatedAt`        | 文字资料最近更新时间；由 Prisma 更新维护，直接 SQL 更新不会自动刷新。                      |

## PlanVersion

用户计划版本：保存当时资料和训练目标快照；禁止 UPDATE，修改必须插入新版本。

| 字段        | 中文说明                                                                                                                                                                                                                                                                              |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`        | 计划版本记录唯一编号（UUID，主键）；不是用户可见的递增版本号。                                                                                                                                                                                                                        |
| `userId`    | 所属用户编号，关联 User.id；与 version 共同构成唯一约束。                                                                                                                                                                                                                             |
| `version`   | 同一用户的计划版本号，从 1 开始；不是软件版本或备份格式版本。                                                                                                                                                                                                                         |
| `snapshot`  | 不可变计划 JSON 快照：包含 version、reason、profile、adjusted、days，可附 editablePlan 手动/外部草稿及 planOverrides 替代清单；days.actions 保存 exerciseId、name、unit、sets、targetMin、targetMax、restSeconds、reason、acknowledged。当前为规则模板，不是真实 AI；旧版本不得覆盖。 |
| `createdAt` | 计划版本创建时刻，带时区时间戳。                                                                                                                                                                                                                                                      |

## Workout

一次训练记录：引用同账户的计划版本，保留当时名称、起止时刻与状态；每个账户最多一项进行中训练。

| 字段          | 中文说明                                                                                                        |
| ------------- | --------------------------------------------------------------------------------------------------------------- |
| `userId`      | 所属用户编号，关联 User.id；与 id 组成联合主键，并限定引用计划的账户归属。                                      |
| `id`          | 训练稳定编号；同一编号可以在不同账户独立存在，不按日期或名称识别训练。                                          |
| `planVersion` | 本次训练采用的计划版本号；与 userId 关联 PlanVersion，后续新计划不改写此记录。                                  |
| `planName`    | 训练采用的计划名称快照；保留当时名称，不随当前计划改名而变化。                                                  |
| `date`        | 用户本地训练日历日期（YYYY-MM-DD），不是 UTC 起止时刻，也不表示某个瞬间。                                       |
| `status`      | 训练状态：active 进行中、completed 已完成；每账户最多一个 active。                                              |
| `startedAt`   | 训练开始时刻，带时区时间戳；旧版归档缺失时为空，不推测时间。                                                    |
| `completedAt` | 训练结束时刻，带时区时间戳；未完成或旧记录缺失时为空，不得早于已知开始时刻。                                    |
| `notes`       | 训练备注或旧数据归档说明；默认空字符串。                                                                        |
| `origin`      | 记录来源：manual 新建训练、legacy 旧版归档；不是动作库来源。                                                    |
| `revision`    | 训练修改版本，初始为 1，每次训练事务保存递增；修改与删除提交 expectedRevision，不一致返回 409，防止旧页面覆盖。 |

## WorkoutExercise

一次训练中的动作实例：名称、单位与目标为当时快照；动作实例 ID 与动作库 ID 不同。

| 字段           | 中文说明                                                                                                                                                          |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `userId`       | 所属用户编号；与 workoutId、id 组成联合主键，限定训练动作归属。                                                                                                   |
| `workoutId`    | 所属训练编号；与 userId 关联 Workout，删除训练时级联删除动作实例。                                                                                                |
| `id`           | 本次训练内的动作实例编号，用于定位编辑；不是公共动作库 exerciseId。                                                                                               |
| `exerciseId`   | 跨训练比较用的稳定动作标识；保留旧版未知动作，不设置强制目录外键；历史身份禁止修改。                                                                              |
| `name`         | 当次动作名称快照，不随目录译名改变。                                                                                                                              |
| `unit`         | 实际记录单位：reps 次数或 seconds 秒；不允许 unspecified，保存后禁止改变单位。                                                                                    |
| `position`     | 动作在本次训练中的排列位置，从 0 开始；同一训练中位置唯一。                                                                                                       |
| `prescription` | 当时计划目标 JSON，可为空以兼容旧记录：sets 组数、targetMin/targetMax 次数或秒数、restSeconds 休息秒数、reason 安排说明；单位由外层 unit 决定，不是实际完成成绩。 |

## WorkoutSet

实际完成的训练组：负重、次数或秒数、RIR 和不适反馈；不等于计划目标。

| 字段                | 中文说明                                                                                       |
| ------------------- | ---------------------------------------------------------------------------------------------- |
| `userId`            | 所属用户编号，与 workoutId、workoutExerciseId、id 组成联合主键。                               |
| `workoutId`         | 所属训练编号，与 userId 共同限定训练归属。                                                     |
| `workoutExerciseId` | 所属当次动作实例编号，关联 WorkoutExercise.id；不是动作库编号 exerciseId。                     |
| `id`                | 实际训练组的稳定编号；不能以数值相同判定同一组。                                               |
| `position`          | 组在当前动作内的排列位置，从 0 开始，当前动作内唯一。                                          |
| `loadKg`            | 实际负重，单位千克，十进制保留三位小数；录入边界 0–400 千克，不是推荐负重。                    |
| `value`             | 实际完成数量，按所属动作 unit 解释：reps 为 1–100 次，seconds 为 1–3600 秒；不能将秒数当次数。 |
| `rir`               | 估计剩余次数：0、1、2、3；3 表示至少三次，缺失时为空，不等于实际完成次数。                     |
| `pain`              | 是否报告疼痛或不适（true 是、false 否，默认 false）；是主观反馈，不是诊断结果。                |

## WeightEntry

体重测量记录：按稳定编号保留，每个用户同一天可以有多次测量，不按同数值去重。

| 字段     | 中文说明                                                                            |
| -------- | ----------------------------------------------------------------------------------- |
| `userId` | 所属用户编号，关联 User.id；与 id 组成联合主键。                                    |
| `id`     | 体重记录稳定编号；不是测量日期。                                                    |
| `date`   | 用户本地测量日历日期（YYYY-MM-DD）。                                                |
| `kg`     | 测量体重，单位千克，十进制保留三位小数，必须大于 0；与 Profile 中当前体重资料区分。 |

## WriteReceipt

第七份迁移新增成功写入回执；当前共 12 张表、87 个字段（含迁移管理表）。

| 字段      | 中文说明                                                            |
| --------- | ------------------------------------------------------------------- |
| userId    | 所属账户 UUID，与 key 组成联合主键；关联 User，删除账户时级联清理。 |
| key       | 客户端随机请求 UUID；每次新操作生成，重试沿用，与训练编号区分。     |
| digest    | 方法、路径及规范化请求体的 SHA-256，64 位；防止同编号提交不同内容。 |
| result    | 首次成功响应 JSON；与业务写入同事务保存，重复请求返回原响应。       |
| createdAt | 首次成功提交时刻（带时区）；当前回执保留至账户删除。                |

## ImportJob

第 6 个迁移新增备份预览任务；当时共 11 张表、82 个字段（含迁移管理表）。

| 字段        | 中文说明                                                              |
| ----------- | --------------------------------------------------------------------- |
| id          | UUID 迁移任务编号；用于确认、取消和重复请求回执。                     |
| userId      | 所属账户，关联 User.id；接口固定取登录会话，不接受客户端归属。        |
| digest      | 规范化备份事实的 SHA-256，64 位；与账户组成唯一索引，防重复导入。     |
| fingerprint | 预览时账户业务资料的 SHA-256，64 位；确认时检查其他页面是否修改记录。 |
| payload     | 已验证的迁移资料 JSON，待确认时短期保存；确认或过期后清空，不含照片。 |
| status      | pending 待确认、confirmed 已确认、expired 已过期。                    |
| result      | 预览汇总或确认回执 JSON；包含新增/跳过条数、版本映射与确认时刻。      |
| expiresAt   | 预览有效期截止时刻（带时区）；30 分钟，过期不能确认。                 |
| createdAt   | 任务创建时刻（带时区），不是历史训练日期。                            |

## _prisma_migrations

Prisma 数据库结构迁移管理表；由工具维护，不是用户业务资料。

| 字段                  | 中文说明                                            |
| --------------------- | --------------------------------------------------- |
| `id`                  | 迁移执行记录唯一编号，由 Prisma 管理。              |
| `checksum`            | 迁移文件校验值，用于检查已应用的迁移是否被改写。    |
| `finished_at`         | 迁移完成时刻，可为空；不表示用户记录更新时间。      |
| `migration_name`      | 迁移目录名称，对应 prisma/migrations 中的结构变更。 |
| `logs`                | 迁移工具执行日志，可为空，由 Prisma 维护。          |
| `rolled_back_at`      | 迁移被标记回滚的时刻，可为空，由 Prisma 维护。      |
| `started_at`          | 迁移执行开始时刻。                                  |
| `applied_steps_count` | 迁移工具记录的已执行步骤数量，不是训练组数。        |

## 在 Navicat 查询全部字段说明

下面只读取表结构与注释，不读取个人资料或登录凭据。

```sql
SELECT c.relname AS "表名", obj_description(c.oid, 'pg_class') AS "表说明",
       a.attname AS "字段名", format_type(a.atttypid, a.atttypmod) AS "类型",
       col_description(c.oid, a.attnum) AS "字段说明"
FROM pg_class c
JOIN pg_namespace n ON n.oid = c.relnamespace
JOIN pg_attribute a ON a.attrelid = c.oid
WHERE n.nspname = 'public' AND c.relkind = 'r'
  AND a.attnum > 0 AND NOT a.attisdropped
ORDER BY c.relname, a.attnum;
```

直接在 Navicat 修改行数据会绕过 API 校验、并发检查和 Prisma 自动更新时间；开发测试优先使用独立测试数据库。计划版本和历史动作单位仍受数据库不可变约束保护，不通过删除约束来修改历史。
